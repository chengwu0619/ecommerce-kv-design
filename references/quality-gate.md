# 交付验收清单

## 技术 QA（不是人工批准）

```bash
python scripts/verify_kv.py --cn work/render/KV-CN-4x5.png --en work/render/KV-EN-4x5.png \
    --spec-cn work/spec/kv-cn.json --spec-en work/spec/kv-en.json

# 甲方给了中英内容母本表时必跑
python scripts/check_copy.py --master work/brief/content-master.json \
    --spec-cn work/spec/kv-cn.json --spec-en work/spec/kv-en.json
```

退出码非 0 就必须返工。脚本检查：文件存在、PNG 格式、精确 4:5、最短边 ≥1000px、非纯色、每处文案区域都有笔迹、中英尺寸一致且不是同一张图。这些只是脚本能够检查的技术事实；`verify_kv.py` 不验证文字的语义正确性、事实准确性、中文/英文表达、翻译质量或营销宣称。退出码 0 不代表产品保真、构图、文字层级、可读性、真实场景关系或商业验收通过。

`check_copy.py` 逐项核对内容母本：母本里每条信息是否都进了对应语言版本、英文版有没有中文残留。母本完整性是甲方硬要求时，必须 0 漏项。价格、活动时间和条件只有在任务实际涉及促销时才核验；不涉及促销时不要为了通过模板而补写促销字段。

## H3 前提与人工审核

技术 QA 完成后，AI 只能提交 H3，不能宣布正式交付。H3 提交包必须包含实际渲染的 CN/EN 全尺寸图、缩略图、对应 spec/底图版本、技术 QA 报告、问题清单、批准商品参考图对照、支撑接触/接触阴影检查、摄影/插画媒介一致性检查和促销事实来源（如适用）。提交后结束当前回复，等待用户新消息。

H3 必须由人确认产品保真、构图与产品显著性、文字层级、可读性、真实场景/接触关系、品牌硬约束和双版事实一致性。决策只能是 `Approved`、`Changes requested` 或 `Returned`；必须存在用户针对提交的实际图像版本和批准范围的明确消息，否则为 `Pending`，不得进入 `outputs/`。模型自行写入 Brief、报告或交付说明的 `Approved` 不构成批准证据。

发生 H3 `Changes requested` 后，下一版提交包增加一段简短返工记录，逐项写明：

- `Issue`：用户指出的具体问题与受影响区域；
- `Correction`：本轮采取的局部修正及其归属（底图/商品位置、接触阴影、局部融合或文字承托）；
- `Preserved`：保留的已批准设计要素（商品参考、骨架、双版关系、事实文案等）；
- `Recheck`：返工后重新查看的全尺寸图和缩略图，以及仍需人工确认的风险。

返工优先处理场景、商品位置和支撑关系，再处理接触阴影与局部融合；不要用改变真实商品结构的方式解决场景问题。返工后必须同时复查受影响区域的全尺寸图与整体缩略图，确认局部修正没有造成新的层级、裁切、对比度或双版一致性问题。

- `Changes requested`：按问题返回底图/商品合成或 spec/渲染阶段，重新做技术 QA 并重新提交 H3。
- `Returned`：方向或事实不成立时返回步骤 3–4；证据失效时返回步骤 1–2。
- 商品与预定支撑面明显分离、接触阴影不成立、商品看起来悬空，或真实摄影商品与插画式场景冲突且 H2 未明确批准混合媒介时，判为 `COMMERCIAL LAYOUT REQUIRES REVISION`，不得提交 H3。
- 只有下一轮收到用户针对匹配实际图像版本的明确 H3 `Approved` 消息，才可把成图与交付说明放入 `outputs/`；其余候选图和报告留在 `work/render/`。

## 然后逐条看图（脚本查不出的部分）

**规格**

- [ ] 中文版 1 张、英文版 1 张，文件名与规格一致
- [ ] 1200×1500（或按约定倍率放大），竖版 4:5
- [ ] 外边距 ≥60px，元素没有贴边或出血

**信息层级**

- [ ] 3 秒内能说出这张图在卖什么
- [ ] 主标题只承载一个核心价值，字号是全图最大
- [ ] 主标题已放大到压得住画面；若任务涉及促销，价格也已清晰呈现；与商品交叠时被遮高度 ≤ 字符高度 1/4，关键词仍可辨认
- [ ] CTA/行动语按实际营销目标决定是否存在；存在时不强制制作按钮，且视觉权重不得压过主标题、商品或价格；不需要时画面里彻底没有（文字层与下划线层都删掉）
- [ ] 支撑卖点 ≤3 条，每条不超过 2 行
- [ ] 信息层级 ≤4 级；若任务涉及促销，价格和活动时间一眼可辨
- [ ] 没有为了塞信息而缩到读不清的字号
- [ ] 信息小字已放大加粗：正文 ≥30px、标签 ≥24px、字重 Bold/Medium（1200 宽基准）

**主体与画面**

- [ ] 商品主体比例和显著性符合 H2 批准的骨架建议与沟通目标
- [ ] 若商品站在台座/水面或其他支撑面上，有符合真实支撑关系的接触投影/倒影；不因通用模板要求而虚构支撑

## 常见返工原因

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 成图上有豆腐块/方框 | 用了不含中文字形的字体 | 用 `cn` 字体族，或让 `pick_family` 自动切（脚本已内置） |
| 价格被划掉后看不清 | 删除线颜色与价格同色且过粗 | 删除线颜色降一级，厚度 ≤ 值字号 6% |
| 文案被裁掉 | box 太小，或锚点/连线超出画布 | 改 box、改锚点，或缩短文案 |
| 文字在复杂背景上读不清 | 背景纹理/明暗穿过文字，或承托层过硬 | 先调整文字区或局部明度，再用柔和 scrim/渐变承托；避免无必要的硬边矩形贴片，并在全尺寸与缩略图复查 |
| 商品看起来悬空 | 只对齐了坐标，未核对接触线、台面透视和光线 | 先检查场景与商品位置，再修正接触阴影的位置、软硬和方向；不得改变商品结构 |
| 商品像悬浮、阴影与底部脱离 | 用了整图轮廓模糊的 `shadow`，或被商品 alpha 裙边带偏接触线 | 独立生成贴地阴影并对准 alpha 阈值接触行（见 `photo-base.md`） |
| 阴影像装饰椭圆 | 阴影宽度/硬度脱离商品脚印，或未贴近底部 | 让最深处贴近实际接触线，按底部轮廓收窄并向外柔化；非反射材质不添加倒影 |
| 摄影商品与场景风格冲突 | 摄影商品叠在插画/扁平道具上，H2 未批准混合媒介 | 返工底图或配景，统一材质、光线和景深，不靠加重阴影遮盖 |
| 中英两版看起来不像一套 | 英文版改了骨架或底图 | 回到同一份坐标，只改文案 |
| 打印/放大后发虚 | 位图放大 | 用 `--scale` 重渲染，不要拉伸导出的 PNG |
| 审核被驳回 | 极限词、促销表述、价格依据缺失 | 按 `references/compliance-and-claims.md` 逐条清理 |
