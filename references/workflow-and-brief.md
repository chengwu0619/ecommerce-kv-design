# 工作流程与 brief

## 工作目录（固定约定）

所有产物都放在项目根目录下，用户可见的最终交付只进 `outputs/`，中间文件全在 `work/`。

```text
<项目根>/
├─ outputs/                        最终交付物（只有这里的东西给用户）
│  ├─ KV-CN-4x5.png                中文版主视觉
│  ├─ KV-EN-4x5.png                英文版主视觉
│  └─ 交付说明.md                   受众/主张/证据/价格与时间来源/待确认项
└─ work/
   ├─ input/                       用户原始素材：包装图、实拍图、logo、资质、活动规则截图
   ├─ brief/kv-brief.md            结构化 brief（唯一的需求真相源）
   ├─ spec/kv-cn.json              中文版设计规格（排版的唯一真相源）
   ├─ spec/kv-en.json              英文版设计规格（与 CN 同坐标，仅换文案）
   ├─ base/                        底图：base-cn.png（实拍/抠图合成/生图）与 optional 细节图
   └─ render/                      迭代稿、对比图、report.json
```

规则：

- 规格 JSON 是唯一真相源。改图 = 改 spec 重渲染，不要直接修 PNG。
- 中英双版共用同一套坐标。英文版只允许改文案与必要的框宽/字号，不允许改骨架。
- 底图一律放 `work/base/`，不进 `outputs/`。

## 七步流程

1. **建档定资料**：建目录，把用户给的素材放 `work/input/`。素材是图片时先看清楚再引用，不要凭文件名猜内容。
2. **写 brief（Gate 1）**：按下表填 `work/brief/kv-brief.md`。信息缺口分两类处理：影响主标题/价格/时间的算"阻塞项"，一次性问清；其余按合理假设推进并在交付说明里标"待确认"。
3. **定受众与单一主张**：一句话写完「给谁 / 什么场景 / 解决什么 / 为什么现在买」。主标题只承载一个核心价值，支撑卖点最多 3 条。
4. **选骨架（Gate 2）**：从三套 archetype 里选一套并说明理由（见 `references/visual-system.md`）。用户已指定参照风格时以用户的为准。
5. **定底图**：实拍优先；有实拍无场景就抠图 + 画布合成；都没有就生图或先用占位底图出布局稿（见 `references/photo-base.md`）。中英双版共用同一张底图。
6. **写规格并渲染**：复制 `assets/templates/` 里最接近的骨架到 `work/spec/kv-cn.json`，改文案与坐标；再复制成 `kv-en.json`。渲染后**必须真正打开成图看**，再决定是否重渲染。
7. **合规与验收（Gate 3）**：跑 `scripts/verify_kv.py`，逐条过 `references/quality-gate.md`，然后写交付说明。

## 缺口处理规则

| 缺口 | 处理 |
| --- | --- |
| 没有价格/活动时间 | 阻塞项，必须问；不允许猜 |
| 没有卖点证据 | 只写商品客观属性（材质、尺寸、结构），不写效果承诺 |
| 没有 logo | 用字标占位（纯文字品牌名），并在交付说明标注"待替换为正式 logo" |
| 没有实拍图 | 用生图底图或占位底图，交付说明必须写明底图来源 |
| 受众不明确 | 按平台 + 类目 + 价格带推断，写进 brief 并标注"推断" |
| 中英双版但英文信息缺失 | 以中文事实为准做本地化重写，不新增事实 |
| 甲方给了中英内容母本表 | 把母本落成 `work/brief/content-master.json`，渲染后用 `scripts/check_copy.py` 核对 0 漏项 |
